# 自動取込（社内PCで動かすスクリプト）

社内の共有フォルダに置かれた **出荷明細**・**売上高（日次・月次）** のファイルを、
平日の昼に自動でアプリへ取り込みます。

クラウド（Vercel）からは社内の共有フォルダが見えないため、社内PCの
**タスクスケジューラ**でこのスクリプトを動かし、PCからアプリへ送ります。
ファイルの読み取りは画面の「取込」と同じコードを使うので、取り込まれる内容は画面から取り込んだときと同じです。

```
社内の共有フォルダ ──(平日12:00 タスクスケジューラ)──> 社内PC: auto-import.mjs ──(鍵つきで送信)──> アプリ
                                                                                      └─> 管理者へ結果メール
```

## 何を取り込むか

| 種類 | フォルダ | 取り込み方 |
|---|---|---|
| 出荷明細（MBの出荷明細） | `folders.ship` | まだ取り込んでいない日を、古い日から1日ずつ取り込んで判定する（画面の「まだ取り込んでいない日だけ」と同じ）。最後に取り込んだ日も、新しいファイルに載っていれば取り込み直す（その日の分が出そろっていなかったときのため） |
| 売上高（日次・当月の累計） | `folders.salesDaily` | フォルダの**いちばん新しいファイルだけ**を取り込む。データの日付は**ファイルの更新日の前の日**（画面の既定「昨日」と同じ考え方） |
| 売上高（月次・確定） | `folders.salesMonthly` | 新しいファイルを取り込む。前の月の月次を取り込んだら、最新の日次を入れ直す（案件の実績が前の月に戻ったままにならないように） |

- 一度取り込んだファイルは**中身**で覚えておき（`auto-import.state.json`）、同じ中身なら二度取り込みません。毎日同じ名前で上書きされるファイルでも、中身が変われば取り込みます。
- 更新日が `lookbackDays`（既定10日）より前のファイルは見ません。初回に過去のファイルをまとめて取り込まないためです。
- 取り込めなかったファイルは記録しないので、次の実行でもう一度取り込みます。
- 結果は毎回アプリに記録し、管理者へメールで知らせます（`notify` が `always` のとき。`error` にすると取り込めなかったときだけ）。
  うまくいった日もメールが届くので、**メールが来ない日はPCが止まっている**と気づけます。
  最後の実行は、アプリの「管理者画面 → 連携の状況」でも見られます。

## 1. アプリ側の準備（最初に1回）

1. **自動取込の専用の利用者を作る**
   管理者画面で利用者を追加します（例：ログインID `auto-import`、氏名「自動取込」、役割 **管理者**、支店・営業所は空でよい）。
   取込履歴の「取込者」にこの氏名が出ます。**この利用者は画面からはログインできません**
   （鍵でしか入れないようにしています）。ふだん使っている管理者のIDを指定しないでください。
2. **鍵を作る**（32文字以上のでたらめな文字列）。例：
   ```
   node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
   ```
3. **Vercel → Settings → Environment Variables** に追加して、再デプロイします。

   | 変数 | 値 |
   |---|---|
   | `AUTO_IMPORT_KEY` | 2で作った鍵 |
   | `AUTO_IMPORT_USER` | 1のログインID（例 `auto-import`） |

   結果メールは、お問い合わせの通知と同じ `RESEND_API_KEY` で送ります。
   宛先は、メールを登録している管理者と `MAIL_NOTIFY_TO` です。

鍵で入れるのは取込に要る操作だけです（案件の書き換えや利用者の管理はできません）。
それでも鍵は管理者のパスワードと同じように扱い、漏れたら作り直してください。

## 2. スクリプトを組み立てる

リポジトリの一番上で：

```bash
npm run build:auto-import
```

`client/auto-import/dist/` に次のファイルができます。このフォルダを社内PCへコピーします。

| ファイル | 内容 |
|---|---|
| `auto-import.mjs` | スクリプト本体（Excelの部品も入っているので `npm install` は不要） |
| `run.cmd` | タスクスケジューラから呼ぶファイル |
| `auto-import.config.example.json` | 設定の見本 |
| `README.md` | この説明 |

画面のファイル読み取り（`client/src/shipColorClient.ts`・`surveyImportClient.ts` など）を直したときは、
組み立て直して社内PCの `auto-import.mjs` を置き換えてください。古いままだと画面と読み方がずれます
（版はログと結果メールの「実行したPC」の欄に出ます）。

## 3. 社内PCの準備

1. **Node.js 22 以上**（LTS）を入れる。https://nodejs.org/ja のインストーラーで入れれば `node` が使えるようになります。
2. 例として `C:\auto-import\` を作り、2の `dist` の中身をコピーする。
3. `auto-import.config.example.json` をコピーして **`auto-import.config.json`** を作り、中身を書き換える。

   ```json
   {
     "appUrl": "https://sales.paloma-pf.com",
     "key": "AUTO_IMPORT_KEY と同じ値",
     "folders": {
       "ship": "\\\\fileserver\\share\\出荷明細",
       "salesDaily": "\\\\fileserver\\share\\売上高\\日次",
       "salesMonthly": "\\\\fileserver\\share\\売上高\\月次"
     },
     "notify": "always",
     "lookbackDays": 10,
     "basicAuth": { "user": "", "pass": "" },
     "vercelBypass": ""
   }
   ```

   - フォルダは **`\\サーバー名\共有名\...` の形**（UNCパス）で書きます。`Z:\` のようなドライブ文字は、
     ログオフ中に動くタスクからは見えないことがあります。JSONの中では `\` を **`\\` と2つ重ねて**書きます。
   - 使わない種類は行ごと消します（例：月次を自動にしないなら `salesMonthly` を消す）。
   - アプリ側のBasic認証（`BASIC_AUTH_USER` / `BASIC_AUTH_PASS`）を使っているときは `basicAuth` に入れます。
   - VercelのPassword Protectionを使っているときは、Vercel → Settings → Deployment Protection →
     **Protection Bypass for Automation** の値を `vercelBypass` に入れます。
   - 鍵を設定ファイルに書きたくないときは、環境変数 `AUTO_IMPORT_KEY` でも渡せます（設定ファイルより優先）。
   - このフォルダは、タスクを動かす利用者と管理者だけが読めるようにしてください（鍵が入っているため）。

4. **確かめる**（取り込まずに、つながるか・何を取り込むかだけを見ます）

   ```
   cd C:\auto-import
   run.cmd --check
   ```

   「アプリにつながりました（取込者: 自動取込…）」と、取り込む予定のファイルが出れば準備できています。

## 4. タスクスケジューラに登録する（平日12:00）

コマンドプロンプトで（`<Windowsの利用者>` は共有フォルダを読める利用者）：

```
schtasks /Create /TN "価格改定進捗 自動取込" /TR "C:\auto-import\run.cmd" /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 12:00 /RU <Windowsの利用者> /RP
```

または「タスク スケジューラ」の画面で：

- トリガー：毎週・月〜金・12:00
- 操作：プログラムの開始 → `C:\auto-import\run.cmd`（開始：`C:\auto-import`）
- 全般：「ユーザーがログオンしているかどうかにかかわらず実行する」（共有フォルダを読める利用者で）
- 条件：「コンピューターをAC電源で使用している場合のみ…」は外しておくと、ノートPCでも動きます
- 設定：「スケジュールされた時刻にタスクを開始できなかった場合、すぐにタスクを実行する」に入れておくと、
  12時にPCが落ちていても、立ち上げたときに動きます

登録したら、タスクを右クリック →「実行する」で一度動かし、結果メールとログを確かめてください。

## ログと記録

| ファイル | 内容 |
|---|---|
| `logs\auto-import-YYYY-MM.log` | 実行のたびの記録（月ごと） |
| `auto-import.state.json` | 取り込み済みのファイルの記録。消すと、`lookbackDays` 以内のファイルを取り込み直します |

終わったときの戻り値：0＝すべて取り込めた／1＝取り込めなかったものがある／2＝設定や接続の誤りで止まった
（タスクスケジューラの「前回の実行結果」に出ます）。

## うまくいかないとき

| 出る文言 | 見るところ |
|---|---|
| 自動取込の鍵が違います | 設定ファイルの `key` と Vercel の `AUTO_IMPORT_KEY` が同じか。Vercelは変えたあと再デプロイが必要 |
| AUTO_IMPORT_USER … を管理者にしてください | 管理者画面で、その利用者の役割を管理者にする |
| フォルダを開けません | タスクを動かすWindowsの利用者でそのフォルダを開けるか。ドライブ文字ではなくUNCパスで書く |
| アプリにつながりません（… ENOTFOUND / ETIMEDOUT） | インターネットへプロキシ経由で出るPCなら、`run.cmd` のプロキシの2行を有効にする |
| アプリにつながりません（… SELF_SIGNED_CERT / UNABLE_TO_GET_ISSUER_CERT） | 会社の通信の検査で証明書が差し替わっている。`run.cmd` の node に `--use-system-ca` を足す |
| ファイルの月と、更新日から見たデータの日付の月が違います | 日次のフォルダに当月の累計ではないファイルが置かれている。取り込むファイルだけを置く |
